## TJU自动综测

自动给全班同学填综测互评的分数 (德智体美劳五项), 一次跑完整个名单.

> Fork 自 [phuturesh/auto-comprehensive-assessment](https://github.com/phuturesh/auto-comprehensive-assessment).
> 上游那版写于学校还在用"填学号当密码、免验证码"登录的时候; 学校换成 CAS 统一身份认证之后,
> 登录表单没有路由了, 页面结构也整个变了, 上游脚本第一步就报 `NoSuchElementException`.
> 这个 fork 把它改到了现在的页面结构上, 并且加了几层防止评错人 / 评错分的检查.

## 和上游的主要区别

| | 上游 | 这个 fork |
|---|---|---|
| 登录 | 自动填学号当账号密码 | 学校已改 CAS, 改成在浏览器窗口里手动登录, 脚本等你登完再继续 |
| 进入打分页 | 在名单页翻页 + 点链接 + `driver.back()` | 先收集整份名单, 再按学号直接打开 `/evaluation/list/<planId>/<学号>` |
| planId | — | 从点开的第一个打分页 URL 里自动识别 (每学期会变) |
| 每页人数 | 硬编码 10 人 | 按表格实际行数, 最后一页不满也不会越界 |
| 五项分数 | 按输入框出现顺序填 | 从 DOM 里读出每个框对应哪一项再填, 认不出来会明确告诉你 |
| 重复提交 | 无保护 | 只评状态为"未评价"的人, 重跑不会重复提交 |
| 空白页 | — | 这系统进页面常常一片空白, 脚本会自动刷新一次 |
| 试跑 | 无 | `DRY_RUN` 只填不提交, 确认无误再真提交 |

翻页那一条是重点: 上游那种"翻页 → 点开 → 填 → back() → 再翻页"的流程有竞态 ——
`back()` 之后列表会掉回第 1 页, 而跳页有时还没生效就把行读走了, 结果是**把第 1 页的人当成第 2 页的人再评一遍, 第 2 页有人整个被漏掉**.
实测确实复现过. 现在打分完全不依赖翻页, 这类问题从根上没有了.

## Usage

需要 selenium:

```shell
pip install selenium
```

改脚本开头的配置, 然后运行:

```shell
python auto_fill.py
```

- `grades`: 德智体美劳五项分数, **按你们学院和年级的规则改**. 本科生和研究生每年的满分和小项上限都不一样; 给分超上限服务器会自动截到上限, 但那不一定是你们学院规定的满分.
- `page_num`: 名单一共几页 (只用来收集学号).
- `DRY_RUN`: 默认 `True`, 只填不提交. **提交不可撤销**, 所以先跑一遍 dry run, 看清楚打印出来的配对结果和分数, 再改成 `False` 真提交.
- `ONLY_UNEVALUATED`: 默认 `True`, 只评"未评价"的人.
- 默认用 Edge, 想换 Chrome/Firefox 改 `webdriver.ChromiumEdge()` 那一行.
- `ENTRY_URL` 留空就直接开名单页让你手动登录. 如果填了从学校入口拿到的带 token 直链可以省掉登录, 但**别把带 token 的地址提交到仓库** —— 那是你账号的会话凭证.

跑起来之后在弹出的浏览器窗口里完成统一身份认证, 脚本检测到名单出现就会自动接着填. 每个人提交后会把服务器的提示 (比如"保存成功") 打出来.

## 页面结构又变了怎么办

学校改前端的时候不会通知你. 别对着选择器猜, 先跑:

```shell
python record_once.py
```

你手动打一次分, 它会把打分页的真实结构录下来: URL、是弹窗还是独立路由、每个输入框的 class / placeholder / 旁边的文字、所有按钮的文字, 以及整页 HTML (`record_*.html`).
照着改比猜快得多. `record_*.html` 里有全班的姓名学号, 已经在 `.gitignore` 里, 别提交.

## Appendix

如果你从来没用过 python, 用的还是 Windows: 安装 python 时务必在 Optional Features 里勾选 pip, 否则上面那条 `pip install selenium` 用不了.
